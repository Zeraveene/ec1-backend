# Classic legacy save viewer

In the shared admin dashboard, choose EC1 admin → PlayFab (legacy). Search exact Classic PlayFab ID, account email, username or title display name, then open a result. This works for accounts with no migrated backend player row.

The Account tab shows the projected account profile, username/email, save timestamp, playtime, gold, ruby and stage progress. The Inventory tab shows searchable bag equipment, materials and consumables, including stack quantities. The Heroes tab follows the EC2 inspector layout with Classic's Alaster, Edna, Louisa and Zerav (`soul`): STR/INT/AGI/VIT, four equipment slots (weapon/armor/gloves/shoes), four skills, four masteries, selected costume and weapon transmog. Missing values say “Not recorded”; zero values remain zero. Historical cloud exports often omitted selected costume/transmog preferences, so ownership flags are never used to guess equipped appearance.

The EC1 Worker owns authenticated `GET /api/classic-admin/legacy?query=…` and `GET /api/classic-admin/legacy/:id` routes. They use the existing central Discord session introspection and revalidate membership for every request. The optional private `AdminWorkspace` RPC also exposes `legacy-search`/`legacy-player`; the EC2 gateway maps fixed GET routes under `/api/admin/games/ec1/legacy`. Every authorized lookup/view attempt is audited without storing search text, emails or save content. Responses use `Cache-Control: no-store`.

Existing EC1 `PLAYFAB_TITLE_ID` and server-side `PLAYFAB_SECRET_KEY` are required. Admin reads are independent of `LEGACY_MIGRATION_ENABLED`; viewing does not activate migration or player features. Only `Admin/GetUserAccountInfo` and `Server/GetUserData` are callable, with the latter limited to `CLOUD_ALL_DATA` and `Playtime`. PlayFab remains immutable. Account-not-found is distinguished from credential/configuration/network failures. Only safe profile and gameplay projections reach the browser.

Internal admins can edit gold, ruby, stage progression and material/consumable quantities, or remove bag entries. Changes remain a local draft until Save changes is clicked. `GET /api/classic-admin/legacy/:id/editor` preserves the complete original source in private EC1 storage and returns an actor-bound review token. `POST /api/classic-admin/legacy/:id/revisions` applies the validated patch to that full snapshot, preserving unknown fields and nested string JSON. Publication uses verified immutable R2 staging, an atomic conditional D1 head update and audit, plus operation-id replay protection. A changed source or revision rejects the save and requires an explicit reload; an uncertain response can be retried with the same operation. Equipped items are unaffected by bag removals.

These are separate backend recovery revisions, read preferentially by this viewer. They do not write PlayFab, create a migrated player, activate migration, or replace a player's active cloud backup. Migration `025_legacy_admin_revisions.sql` must be applied before enabling editing; existing read-only viewing remains available without it. Roles other than internal stay read-only.

The projection decodes a legacy preference dictionary, nested hero/equipment JSON strings, older unquoted-`$` positional fields and schema-1 records. `src/admin/legacy-keys.json` follows the exact `SaveMigration.LegacyKeys` order in the sibling Classic Unity client. Ability labels follow `Assets/_Contents/Data/Heroes/*.asset` (`tier1..4`, `p1..4`); costume labels follow `HeroCostumeNames.cs`. Equipped and bag equipment share a hover/focus/tap inspector for final main stats, substats and a compact socket block. Main stats apply the client's 10% per enhancement-level rule and integer rounding where applicable, while displaying only final values. Substats/socket values remain unscaled; missing sockets are distinguished from recorded empty sockets. The viewer does not recompute full hero combat totals. Legacy inventory splits unquoted `^` sections and `|` entries, retaining duplicate equipment instances and warning on damaged entries without hiding healthy neighbours. Compact non-equipment records resolve static descriptions from the existing item catalog without inventing owned quantities. Damaged sections generate warnings without hiding healthy sections.

Validation uses synthetic saves and intercepted PlayFab requests only. `tests/admin-legacy.test.mjs` covers parsing/projections/error distinctions, `tests/admin-control.test.mjs` covers the authenticated HTTP path, current roles, audit and outbound read allowlist, and `tests/admin-legacy-edits.test.mjs` covers original preservation, immutable revisions, conflicts, replay and publication rollback. This feature requires both backend and shared-dashboard deployment; no deployment or production mutations are part of local implementation. Real-data UI previews remain private local files outside Git.

The compact dashboard omits equipment IDs/type/rarity/level requirements, descriptions, sell prices, base values and explanatory footers from popups. Material and consumable rows show only the Classic atlas icon, title and owned amount.
